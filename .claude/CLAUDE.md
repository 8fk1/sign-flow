# 言語設定
    - 常に日本語で返答してください。
    - 思考の過程も可能であれば日本語で

# 動作設定

    - 毎回、修正計画をあとで辿れるようにどこかに保存してください。
    - 実行の終わりには、最初の依頼がなんだったか、結果どうなったかの詳細を追記してください。また、現在時刻のタイムスタンプ（YYYY-MM-DD HH:MM）と内容を private/HISTORY.md に追記してください。
    - 次に強化する機能の候補、追加する機能の候補を提示
    - 機能追加・バグ修正・UIの変更を行った場合は、CHANGELOG.md の最新バージョンのセクションに内容を追記すること（まだそのバージョンのセクションがなければ追加する）

# テスト実行ルール

    - コードに変更を加えた場合は、完了報告の前に必ず詳細なテストケースの作成後、自動テストを実行して動作検証を行ってください。
    - テストコマンドは `npx playwright test` ( headed / headless は状況に応じて判断 ) を使用してください。
    - テストが失敗した場合は、必ずエラーを修正してテストをパスさせてから報告を行ってください。

# このファイルについての注意

    - 修正計画は `private/plan_*.md` に保存する

# リリース手順

    - `npm run release` の前に必ず `CHANGELOG.md` をユーザー向けの変更内容で更新すること
    - CHANGELOG.md には機能追加・バグ修正など「ユーザーに関係ある変更」だけを書く
    - 内部的な作業ログは `private/HISTORY.md` に書く（CHANGELOG.md には書かない）
    - 形式: `## v{バージョン} ({YYYY-MM-DD})` を先頭に追加
